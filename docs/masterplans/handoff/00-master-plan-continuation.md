# Master Plan continuation brief for MiniMax M3

**Prepared:** 2026-08-27

## The honest state

The Master Plan is **not complete**.  Many bounded, reversible releases are
accepted, but acceptance of a release is evidence only for the exact cells and
function it names.  It is not evidence that its parent district, route,
station, bunker, or the whole plan is done.

The controlling inventory is the [Master Plan Completion Register](../MASTER-PLAN-COMPLETION-REGISTER-2026-08-26.md).  This brief is the continuation
map: it groups the register into work packages, identifies what has been
researched and designed, and says exactly what MiniMax M3 must establish before
it can build.  It intentionally does not convert an old design, screenshot, or
catalogue record into live-world authority.

1. Read this brief and the three domain briefs:
   [Cheyenne and SubTropolis](01-cheyenne-subtropolis.md),

2. Read the current per-area state files linked in the programme table below.
   They supersede historical `HOLD` language when they contain later accepted
   execution/post-state evidence.
3. Begin every proposed mutation with a new immutable source snapshot. The
   latest completed research capture is
   `data/worldsnap-masterplan-frontier-refresh-20260827T053500Z`; it is useful
   for the current frontier contracts but is **not** a reusable live-release
   source guard. Read the [fresh frontier research and design packet](05-frontier-research-and-design-2026-08-27.md)
   before selecting C01, AG-4, or the Cheyenne outer portal.
4. Select one exact, independent scope.  Do not solve an unbounded water,
   lava, gravity, ownership, container, or public-return problem by quietly
   expanding an adjacent release.
5. Compile, preflight, execute, capture, independently QA, and then update the
   controlling current-state record and the completion register.

## Recommended continuation sequence

This is dependency order, not permission to make broad edits.

1. **Evidence refresh:** take a complete source snapshot and update the world
   catalogue/crosswalk only if it is needed for a selected scope.
2. **Resolve finite interfaces first:** MP01 outer-portal/access ownership,
   MP02 B08 purpose/receiver terms, MP08 C1 receiver/return terms, Cobalt PC01
   endpoints/returns, and AG-4 hydrology/ownership.
3. **Build functional local packages:** only exact packages that close a real
   route, access, containment, recovery, or safety gap—not more decorative
   lighting or new duplicate shells.
4. **Build district internals after safe access:** Cheyenne service/public
   programme, SubTropolis occupied programme, Houston lobby/tunnel programme,
   Raven Rock rooms, surface districts, and venue egress.
5. **Build cross-system links:** SYS-01 walk continuity, SYS-02 classified
   PassageWay, and Cobalt station/rail commissioning.
6. **Publish after acceptance:** update maps, screenshots, navigation reports,
   public dashboard content, and the completion register with precise limits.

## Claim vocabulary that must stay exact

- **As-built / post-verified / reversible:** only where a fresh source, guarded
  execution journal, immutable post snapshot, rollback-post-state preflight,
  and independent QA are linked.
- **Design / contract only:** source-bound layout or decision record; emits no
  operation, manifest, RCON call, access reclassification, or commissioning.
- **Survey only:** current measured evidence; not build authority.
- **Held / default-deny:** affected cells are not buildable until their exact
  missing state is supplied.  It does not freeze unrelated disjoint scopes.
- **Public / operating / commissioned:** needs a functional path, endpoints,
  failure/recovery behaviour and the relevant system QA; physical rail or a
  decorative path does not qualify.
