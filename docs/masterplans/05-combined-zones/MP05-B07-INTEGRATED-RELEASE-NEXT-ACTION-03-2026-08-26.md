## Why no physical subpackage can execute now

No fragment preserves both function and reversibility:

- A fluid-only liner/displacement package has no finite topology, receiver, overflow path, or reverse state contract.
- A gravity-only support package either leaves the route and water unresolved or recreates unsupported falling blocks on rollback.
- Removing either cap or opening the headhouse creates a nonfunctional endpoint with no owned exterior receiver.
- A landing/descent-only package leaves the accepted cap, unowned seam, and route endpoint unresolved.
- A lower-lobby-only opening is not an endpoint contract and would create an incomplete route.

Therefore the first physical compiler must consume accepted authority, hydrology, gravity, route, and receiver contracts together. Its forward order is containment, permanent gravity treatment, then route/receiver activation; rollback reverses that hydraulic and gravity-safe dependency order. The normal fresh guarded-release kernel and independent bidirectional normal-walk/end-point QA remain required immediately before and after any live mutation.
